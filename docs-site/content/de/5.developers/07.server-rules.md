**Cubiq Server Rules** ist ein kostenloses Plugin und Server-Mod. Es sagt dem Cubiq Client, was auf deinem Server erlaubt
ist: einzelne Module sperren, erzwingen oder ihre Einstellungen festlegen und begrenzen – global, je Welt oder je
Unterserver.

::note
Cubiq Server Rules steuert nur den **Cubiq Client**. Es ist kein Anti-Cheat: Andere Clients ignorieren es, und ein
veränderter Client kann sich als Cubiq Client ausgeben.
::

## Herunterladen und installieren

Alle Plattformen stecken in einem GitHub-Release:
[github.com/PwiePixel/Cubiq-launcher/releases/tag/server-plugin](https://github.com/PwiePixel/Cubiq-launcher/releases/tag/server-plugin).
Überblick: [Für Server](https://cubiq-launcher.invalid/servers?lang=de).

| Plattform | Datei | Hinweise |
|---|---|---|
| Spigot, Paper, Purpur, Folia | `cubiq-server-rules-bukkit-<version>.jar` | Eine Jar für Minecraft 1.8.8 bis zur neuesten Version. Regeln je Welt. |
| Velocity 3.x | `cubiq-server-rules-velocity-<version>.jar` | Regeln je Unterserver (`servers:`). |
| BungeeCord, Waterfall | `cubiq-server-rules-bungee-<version>.jar` | Regeln je Unterserver (`servers:`). |
| Sponge (API 8 und neuer) | `cubiq-server-rules-sponge-<version>.jar` | Regeln je Welt. |
| Fabric 1.20.1, 1.21.1, 1.21.4, 1.21.11 | `cubiq-server-rules-fabric-<mc>-<version>.jar` | Nur auf dem Server. Config `config/cubiq-server-rules.yml`. |
| NeoForge 1.21.1, 1.21.11 | `cubiq-server-rules-neoforge-<mc>-<version>.jar` | Nur auf dem Server. Config `config/cubiq-server-rules.yml`. |
| Forge 1.20.1 | `cubiq-server-rules-forge-1.20.1-<version>.jar` | Nur auf dem Server. Config `config/cubiq-server-rules.yml`. |

::steps{level="3"}
### Jar herunterladen
Nimm aus dem Release die Datei für deine Server-Software.

### Installieren
Leg sie in den Ordner `plugins` (Plugins) bzw. `mods` (Server-Mods) und starte den Server einmal. Spieler müssen nichts
installieren – der Cubiq Client versteht die Regeln schon.

### Config anpassen
Plugins legen `config.yml` in ihrem Datenordner an (`plugins/CubiqServerRules/` bei Spigot/Paper/Bungee, `plugins/cubiq-server-rules/` bei Velocity, `config/cubiqserverrules/` bei Sponge), Server-Mods `config/cubiq-server-rules.yml`. Danach
`/cubiqrules reload`.
::

::tip
Hinter einem Proxy (Velocity, BungeeCord) gehen die Regeln des Proxys vor einem Cubiq-Server-Rules-Plugin auf dem
Unterserver.
::

## Konfiguration

```yaml
# Cubiq Server Rules – control Cubiq Client features on your server.
# Note: members of the Cubiq team with the "serverrules.bypass" permission can override these rules
# after an in-game confirmation. This is documented on purpose.
modules:            # global
  minimap: false    # false = forced off, true = forced on
  fullbright: false
settings:
  zoom.factor: {max: 4}
  cinematic.freecamFairPlay: true
worlds:             # Bukkit/Sponge/mods: per world; Velocity/Bungee: "servers:" per backend server
  pvp_arena:
    modules: {zoom: false, freelook: false}
message: ""         # optional text shown once to Cubiq Client players
missing-client:     # players whose client does not answer with a Cubiq Client hello
  action: ignore    # ignore | notify | kick
  timeout-seconds: 10
  notify-message: "This server works best with the Cubiq Client."
  kick-message: "Please join with the Cubiq Client."
bypass-permission: cubiqrules.bypass   # players with this server permission get no rules
```

Alles auskommentiert (oder nicht vorhanden) heißt: nichts gesperrt, der Spieler entscheidet.

### modules

`<Modul-ID>: true | false`. `false` sperrt das Modul **aus**, `true` erzwingt es **an**. Ein Modul, das nicht drinsteht,
bleibt Sache des Spielers. Alle IDs: [Modul-IDs](#modul-ids).

### settings

`<Modul-ID>.<Einstellungs-ID>: …` – die Einstellungs-IDs sind die Schlüssel eines Moduls in der Config-Datei des Cubiq
Clients `config/cubiqclient.json` (`flags`, `numbers`, `choices`).

| Form | Bedeutung | Beispiel |
|---|---|---|
| `true` / `false`, eine Zahl oder ein Name | Genau diesen Wert erzwingen (Kurzform von `{value: …}`) | `minimap.fairPlay: true` |
| `{value: x}` | Wert erzwingen – an/aus, Zahl oder Auswahl (über ihren Namen) | `cinematic.smoothing: {value: SMOOTH}` |
| `{min: a, max: b}` | Zahl begrenzen (eine Seite reicht) | `zoom.factor: {max: 4}`, `fullbright.level: {max: 200}` |

Unbekannte Module oder Einstellungen ignoriert der Client – eine Config funktioniert also auch mit älteren und neueren
Cubiq-Client-Versionen.

### worlds / servers

Regeln für einzelne Welten (Bukkit, Sponge, Server-Mods: `worlds:`) oder Unterserver (Velocity, BungeeCord:
`servers:`), jeweils mit eigenen `modules:` und `settings:`. Ein Eintrag dort geht vor den globalen Eintrag mit demselben
Schlüssel; alles andere kommt aus dem globalen Teil.

### message

Optionaler Text, den der Cubiq Client einmal als Cubiq-Hinweis zeigt, wenn die Regeln ankommen. Leer = kein Hinweis.

### missing-client

Was mit Spielern passiert, deren Client nicht innerhalb von `timeout-seconds` mit einem Cubiq-Client-Hello antwortet:

| `action` | Wirkung |
|---|---|
| `ignore` | Nichts (Standard). |
| `notify` | Der Spieler bekommt `notify-message` im Chat. |
| `kick` | Der Spieler wird mit `kick-message` gekickt. |

### bypass-permission

Spieler mit dieser **Server**-Permission (Standard `cubiqrules.bypass`) bekommen gar keine Regeln – für deine Admins und
Builder.

### bypass-players und bypass-op-level

- `bypass-players: []` – Namen oder UUIDs, die keine Regeln bekommen, auf allen Plattformen.
- `bypass-op-level: 0` – nur Server-Mods (Fabric/NeoForge/Forge haben kein Permission-Plugin): Operatoren ab diesem Level
  bekommen keine Regeln (`0` = aus). Auf Fabric wirken `bypass-permission` und `cubiqrules.admin` zusätzlich, wenn LuckPerms
  oder eine andere Mod mit fabric-permissions-api installiert ist.

## Befehle

| Befehl | Wirkung |
|---|---|
| `/cubiqrules reload` | Config neu laden und die neuen Regeln an alle Spieler schicken. |
| `/cubiqrules status <spieler>` | Zeigt, ob der Spieler den Cubiq Client nutzt und welche Regeln gelten. |

Permission `cubiqrules.admin`; bei Fabric, NeoForge und Forge OP-Level 3.

## Cubiq-Team-Bypass

Mitglieder des Cubiq-Teams, deren Rolle das Team-Recht **`serverrules.bypass`** hat, können ein gesperrtes Modul oder eine
gesperrte Einstellung trotzdem benutzen. Wenn sie es ändern wollen, fragt der Cubiq Client zuerst: „Dieser Server sperrt
„Minimap“. Als Cubiq-Team trotzdem benutzen?“. **Ja** hebt genau diese Sperre auf, bis sie den Server verlassen.

- Es gibt ihn, damit das Team Funktionen auf jedem Server testen und Spielern helfen kann.
- Der Spiel-Server erfährt davon nichts und kann es nicht abschalten.
- Er ist bewusst offen dokumentiert: hier, auf der Seite [Für Server](https://cubiq-launcher.invalid/servers?lang=de),
  in der README des Plugins und als Kommentar oben in jeder erzeugten Config.
- Die Ausnahme für dein eigenes Team ist die Server-Permission aus `bypass-permission` – die hast du komplett selbst in
  der Hand.

## Protokoll

Für alle, die eine eigene Umsetzung schreiben wollen. Plugin Messaging (Custom Payload), Inhalt ist UTF-8-JSON als rohe
Bytes (ohne Längenpräfix), höchstens 32 KiB.

| Richtung | Minecraft 1.13 und neuer | Minecraft 1.12 und älter |
|---|---|---|
| Server → Client (Regeln) | `cubiqclient:rules` | `Cubiq\|Rules` |
| Client → Server (Hello) | `cubiqclient:hello` | `Cubiq\|Hello` |

Server registrieren beide Namen, wo die Plattform es erlaubt (gemischte Versionen hinter ViaVersion).

::steps{level="3"}
### Hello
Der Client registriert die Kanäle und schickt nach dem Betreten (Spielphase) `hello`.

### Regeln
Der Server antwortet mit `rules` – immer, auch leer – und schickt sie erneut nach einem Weltwechsel (Proxy:
Serverwechsel) und nach `/cubiqrules reload`.

### Ersetzen und vergessen
Jede `rules`-Nachricht **ersetzt** den bisherigen Regelsatz komplett. Beim Trennen verwirft der Client alle Regeln.
::

Hello (Client → Server):

```json
{"v":1,"client":"cubiqclient","version":"0.20.0","mc":"1.21.11","loader":"fabric","modules":["fps","minimap","zoom"]}
```

Regeln (Server → Client):

```json
{"v":1,
 "modules":{
   "minimap":{"enabled":false},
   "fullbright":{"enabled":false},
   "zoom":{"settings":{"factor":{"max":4.0}}},
   "cinematic":{"settings":{"freecamFairPlay":{"value":true}}},
   "toggleSprint":{"enabled":true}
 },
 "message":"Optionaler Text, den der Client einmal zeigt"}
```

- `enabled: false` = gesperrt aus, `enabled: true` = erzwungen an, fehlt = der Spieler entscheidet.
- `settings.<id>`: `{"value": x}` erzwingt einen Wert (Bool, Zahl oder Auswahl über den Enum-Namen),
  `{"min": a, "max": b}` begrenzt eine Zahl.
- Unbekannte Module und Einstellungen werden ignoriert. Bei `v` größer als 1 liest der Client nur die Felder, die er kennt.

## Codes im Chat oder MOTD

Auch ohne Plugin kann ein Server unsichtbare Codes schicken: jeder Buchstabe mit einem `§` davor, in einer
Chat-Nachricht oder im MOTD. Sie gelten, bis der Spieler den Server verlässt, und wirken auch neben Cubiq Server Rules.

| Code | Wirkung |
|---|---|
| `§t§r§s§n§o§f§r§e§e§c§a§m` (`cubiqnofreecam`) | Freecam aus. |
| `§t§r§s§f§a§i§r§f§r§e§e§c§a§m` (`cubiqfairfreecam`) | Freecam nur mit Fair Play (keine Kamera durch Wände). |
| `§t§r§s§r§e§s§e§t§f§r§e§e§c§a§m` (`cubiqresetfreecam`) | Hebt die Freecam-Codes wieder auf. |
| `§f§a§i§r§x§a§e§r§o` (`fairxaero`) | Fair Play für Minimap und Weltkarte (erzwingt auch Fair Play bei der Freecam). |
| `§n§o§m§i§n§i§m§a§p` (`nominimap`) | Keine Minimap. |
| `§r§e§s§e§t§x§a§e§r§o` (`resetxaero`) | Hebt die Karten-Codes (und die Freecam-Codes) auf. |

Die Karten-Codes sind die verbreiteten Codes anderer Karten-Mods – vorhandene Fair-Play-Plugins wirken also auch beim
Cubiq Client.
